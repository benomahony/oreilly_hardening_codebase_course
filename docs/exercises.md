# Exercises and answers

Read an example, predict the failure, and run it with `uv run FILE`. Implement
the fix in that same file and rerun the same command. Keep its checker intact; undo
your live edit afterward to reset. The finished application in `src/` and its
tests in `tests/` provide further reference.

Paths below are relative to the repository root. The [README](../README.md)
lists the runnable files; this guide explains what each fix changes.

## What each fix changes

Formatting and typing: use concrete `int` inputs and an `int` return, remove unused
imports, and raise a specific `InsufficientStockError` instead of swallowing every
exception. `reserve` is the complete working example of those choices.

Domain language: replace vague managers and booking aliases with stock and
reservation concepts. In the finished domain, `reserve` names the operation and
has one definition; its module and exception use the same vocabulary.

| NASA failure | Correction in the working application |
|---|---|
| NASA01 forbidden API | Call known functions directly instead of evaluating code |
| NASA01 recursion | `reserve_batch` iterates over a bounded tuple |
| NASA02 unbounded loop | Check the 32-item maximum before starting work |
| NASA04 long function | Split unit calculation from batch orchestration |
| NASA05 too few meaningful assertions | Check positive units, nonnegative stock, and conservation |
| NASA05-message | Give each invariant a useful failure message |
| NASA05-single-condition | Give each invariant its own assertion |
| NASA05-constant-assert | Assert properties of inputs and outputs, not just-assigned literals |
| NASA05-redundant-none | Replace a redundant type-shaped check with a business property |
| NASA05-total-op | Do not count string-conversion truthiness as a stock invariant |
| NASA05-guaranteed-len | Check a business upper bound instead of `len(x) >= 0` |
| NASA05-isinstance | Type-check statically and validate external input explicitly |

Test quality: `tests/test_domain.py` uses fixed local inputs (DET/ISO), synchronous
behavior without waiting or input (FST/AUT), real outcomes without mocks or call
assertions (BHV/STR), specific exceptions (SPC), active tests (PRD), and short tests
named after observable behavior (CMP/RDL). `tests/test_infrastructure.py` also
exercises the full request path with the real parser, application, and domain.

Hypothesis: remove the erroneous `+ 1` in the calculation. Keep the general
conservation property in `tests/test_properties.py`; `tests/test_domain.py` already
retains the minimal `(1, 1, 0)` regression case. Generated byte inputs also check
that invalid external requests produce validation errors, never assertion failures.

Documentation: ten minus three is seven. Fix the stale expected output rather than
changing the business behavior. Rerun the documentation example to check its corrected output. The finished
usage guide and both ADRs are also checked by `make check`.

Mutation: add the zero-stock, empty-batch regression to the real application tests.
See [the mutation lesson](mutation.md) for why full coverage missed it.

## Discussion

Which tests keep passing after a harmless internal refactor? Which invariants are
meaningful at runtime? Which surviving mutations are equivalent, and which expose
missing tests? Why is a complete type annotation score insufficient to establish
correctness?

Writable and Inspiring are reviewed by reading the short tests: setup is cheap,
names express intent, and boundary properties suggest further examples. The tool's
optional AI review can support this discussion, but is outside the deterministic,
credential-free gate.
